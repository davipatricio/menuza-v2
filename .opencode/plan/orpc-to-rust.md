# Replace oRPC/Bun APIs with two Rust services, OpenAPI-typed from one contract

Status: active
Updated: S19

## Non-goals

- No rename of tenant → management. Tenant already is the management API (`packages/api-tenant`). User wording "tenant e management" is the same service.
- No third service, no merge into one binary, no gRPC.
- No rewrite of TanStack Start routes, loaders, or UI. `apps/web` only swaps its API client. Not Next.js — that migration already landed (`apps/web/AGENTS.md`).
- Worker moves in this plan, but only after the API cutover. No BullMQ-compatible Rust client unless its Redis layout is proven wire-compatible.
- OAuth2 and MCP move with the tenant service. No new OAuth provider features — parity with `apps/tenant/src/oauth.ts` and `mcp/` only.
- No Prisma client inside Rust. Schema stays in Postgres; Prisma stops being the runtime query layer only after cutover.
- No RLS in this cut. ADR-0001 stays: app-layer `tenant_id` on every query. RLS is a later migration only if sqlx can `SET LOCAL` on the same connection (it can). Not now.
- No hot code swap. Dev reload is process restart (`bacon`).
- No port of all 94 procedures in one step. Foundation first, then commerce (13), then tenant (81) by subdomain.
- No new skill tree. Service docs are `AGENTS.md` files: one per crate root plus one per domain/subdomain folder, same pattern as `apps/web/src/features/*/AGENTS.md`. See the Docs map.

## Target shape

```
crates/
  contract/        DTOs + utoipa + shared error codes (no IO)
  persistence/     sqlx 0.9, tenant-scoped query helpers, baseline migration
  domain/          argon2, sessions, money-as-cents (no HTTP, no axum)
  http/            shared tower layers + extractors, used by both binaries
  api-commerce/    axum binary :3001, router only
  api-tenant/      axum binary :3002, router + oauth + mcp (rmcp)
  worker/          riverqueue consumer over the same pool, no HTTP port
  openapi/         schema emit binary → openapi/{commerce,tenant}.json
apps/web           TanStack Start. orval client behind createServerFn + one island helper
```

OAuth2 endpoints and `/mcp` are deliberately **outside** the OpenAPI documents — the existing oRPC docs do not describe them either. They are protocol surfaces (RFC 6749 / MCP), not panel REST.

One HTTP stack, composed once in `crates/http`, mounted by both binaries. No copied middleware.

Layers, outside-in: request id (reuse inbound `x-request-id`) → catch-panic → timeout 30s → request body limit 1MB → compression → trace (continue inbound `traceparent`) → access log. Then extractors, not layers: `InternalToken` (timing-safe, fail closed), `Session` (cookie `menuza_tenant_sid`), `TenantScope`.

`TenantScope` keeps the live contract: `x-menuza-tenant-id` stays the tenant source for the REST surface, because the web rewrite writes it server-side (`proxy-upstream.ts`) and the worker sends it on internal calls. Rust accepts it **only from a trusted hop** — loopback peer, or `TRUSTED_PROXY_HOPS > 0` with a forwarded host — and rejects it from anything a browser can reach directly. Session-derived scope wins when both exist. A browser can never choose its tenant.

Prod config, both binaries, env-only:

- `MENUZA_ENV=production|development`. `/docs` (Scalar) exists only in development.
- Tokio multi-thread. HTTP/1 + HTTP/2 via axum defaults. `rustls` if TLS is terminated in-process; otherwise Caddy stays in front and the binary binds `HOST=0.0.0.0` in the image, `127.0.0.1` in dev.
- sqlx `PgPoolOptions`: `max_connections` from `DATABASE_POOL_MAX` (default 10), `acquire_timeout` 2s, `idle_timeout` 10min, `max_lifetime` 30min. `statement_cache_capacity` 100. One pool per process.
- Graceful shutdown on SIGINT/SIGTERM: stop accept, drain 15s, close pool, flush OTel. OTel exporter no-op unless `OTEL_EXPORTER_OTLP_ENDPOINT` is set.
- JSON logs in production, pretty logs in development. No secret, cookie, or `authorization` in logs.
- Release profile: `lto = "thin"`, `codegen-units = 1`, `opt-level = 3`, `strip = "symbols"`. Dev profile stays unoptimized so `bacon` restarts stay fast. `panic = "abort"` only on the two binaries, not on libs (tests need unwind).

Stack: tokio 1.54 + axum 0.8 + tower-http 0.7 + sqlx 0.9 + utoipa 6 + utoipa-scalar + tracing-opentelemetry 0.34 + thiserror 2. TS client: **orval**, TanStack Query client, called from `createServerFn` on the server and from one browser helper on islands. Not `openapi-fetch` alone — islands already use Query mutations. Reload: `bacon`. Config: serde struct from env, read at startup, never at import of a lib.

Persistence decisions (no ORM):

- `sqlx` 0.9, Postgres only, `query!` / `query_as!` verified at compile time. CI builds with the committed `.sqlx` offline cache, so no database is needed to check. Anything dynamic (panel list filters) uses `QueryBuilder` inside `crates/persistence`, never in a handler.
- All SQL lives in `crates/persistence`. `domain` receives typed structs; axum handlers never see a `PgRow`. Executor is generic over `PgExecutor` so the same function runs on `&PgPool` or `&mut Transaction` — required for River's transactional enqueue.
- Type mapping is fixed, not per-query, and follows the live schema (verified against `menuza` on 2026-11-02), not Prisma's abstract types:
  - every `id` is `text` holding a UUIDv4 string → `Uuid::new_v4().to_string()`; never a PG `uuid` column.
  - Prisma enums are **`text` + `CHECK (col = ANY (ARRAY[...]))`** in Postgres — there are no PG enum types. Rows carry `String`; a Rust enum with `TryFrom<&str>` validates at the domain edge when the value is branched on. Do not write `#[sqlx(type_name = "...")]`, there is nothing to bind to.
  - timestamps are **`timestamp(3) without time zone`** (Prisma `DateTime`), not `timestamptz` → `chrono::NaiveDateTime`, treated as UTC. Serialize as ISO-8601 with milliseconds and `Z` (`to_rfc3339_opts(SecondsFormat::Millis, true)`) so the JSON matches what `Date.toISOString()` produced.
  - money is `int4` → `Cents(i32)` newtype (`#[sqlx(transparent)]`); `i64` would be wrong.
  - JSON columns → `sqlx::types::Json<T>`.
- Migrations run as a deploy step, not on boot: `sqlx migrate run` under an advisory lock, never from both binaries at startup. `migrations/0001_baseline.sql` is the Prisma-derived baseline (S2).
- If `PgBouncer` is ever put in front (transaction pooling), set `statement_cache_capacity(0)` and disable prepared statements — `query!` will not work in that mode. Not in this plan; recorded so it is not a surprise.
- No ORM means no lazy relations: panel screens that today rely on `include` become explicit joins or two queries in one function. N+1 is a review item, not something a mapper hides.

Migration safety, beyond S2's baseline:

- `_sqlx_migrations` records version, checksum and execution time; sqlx refuses to run if an applied file changed, so migrations are append-only. Rolling back is a forward fix plus a restore — down migrations exist only for files created with `sqlx migrate add -r`, and this plan does not rely on them.
- Each file runs inside one transaction (Postgres transactional DDL), so a failed statement leaves nothing half-applied. A file that needs `CREATE INDEX CONCURRENTLY` must declare `-- no-transaction` and be written to be re-runnable.
- Exactly one runner: the deploy step. Both binaries start without migrating. sqlx takes a Postgres advisory lock while running, which protects against two deploys overlapping but does not make boot-time migration a good idea.
- Every migration session sets `lock_timeout` (e.g. 5s) and `statement_timeout`, so blocked DDL fails instead of queuing behind live queries and freezing the table.
- Schema changes on populated tables use expand/contract: add nullable column → backfill in batches → `NOT VALID` constraint → `VALIDATE CONSTRAINT` → drop the old column in a later release. Never `SET NOT NULL` or change a type in place on a table that serves traffic.
- The baseline cutover is the one irreversible-looking step: before inserting the baseline row into `_sqlx_migrations`, compare the live schema against `contract.prisma` (column names/types/nullability). If they differ, stop — sqlx will never detect that drift for you.
- Performance is a review item, not a driver setting: `EXPLAIN (ANALYZE, BUFFERS)` on the ten heaviest panel reads, no sequential scan on a large table without an index, and pool size from `DATABASE_POOL_MAX` checked against `pg_stat_activity`. Measure at S19 with `oha` against three endpoints; do not quote benchmark numbers from the internet for this schema.

Wire, do not invent: keep ports, cookie name, internal header, error codes, cents, `where tenant_id`, `/livez` `/readyz`. REST paths already in the committed OpenAPI docs become the Rust routes. `/rpc` dies per service only after that service's Start callers have switched.

SSR path stays as it is today; only the last hop changes:

1. `apps/web/src/server.ts` (`createServerEntry.fetch`) → `resolveHost` → it **deletes** any inbound `x-menuza-tenant-id` and re-sets it from the host. That is the trust boundary, and it stays. Rust's `TenantScope` is the second gate (trusted hop only).
2. Same-origin API mounts (`/tenant/*`, `/commerce/*`) go through `proxyUpstream`, which forwards `cookie`, `x-forwarded-host`, `x-forwarded-proto` and drops hop-by-hop headers. OAuth's `publicOrigin()` depends on those two forwarded headers plus `TRUSTED_PROXY_HOPS`.
3. Everything else renders through `createStartHandler(defaultStreamHandler)`. Route loaders call `createServerFn`, which calls a per-request client (`tenantApi(cookie)`) against loopback. No module-level client, no env read at import — the server bundle is shared across tenants.

Constraints that must not be broken while porting:

- Login/register/password-change stay **browser-side** (`src/lib/session-client.ts`). A Start server function does not relay `Set-Cookie`; moving them into SSR silently loses the session cookie.
- Error mapping in loaders: `401` → `null` (screen shows login), `404` → `notFound()`, `5xx` → throw so the error boundary renders. Never render an empty panel for a failed upstream.
- No `useQuery` on the server. Loaders await; islands mutate. That means no dehydration changes in this plan.
- A Rust restart mid-SSR fails the in-flight fetch. Retry idempotent GETs once; surface a 503, not a stack.

## Docs map

Every entry has an owning step; nothing is "documented later".

Two layers, no duplication:

- **Crate root** (`crates/<crate>/AGENTS.md`) — rules for the whole crate: ports, stack, migration policy, what the crate must not depend on.
- **Nested** (`src/**/AGENTS.md`) — only what is wrong or misleading at the crate root: the folder's public surface, its invariants, and what must not be added there. ~15 lines each, mirroring `apps/web/src/features/*/AGENTS.md`. If a line reads true one folder up, it belongs one folder up.

Folder layout mirrors `packages/api-{commerce,tenant}/src/domains/**` one-for-one (including `domains/<domain>/subdomains/<name>/`), so the port is a folder-to-folder diff rather than a redesign. A later flatten is a mechanical `git mv`, not part of this plan.

The nested files are gated by count in S18 rather than enumerated in `scripts/workspace-policy.test.ts`: a hard-coded path list would duplicate this table and break on every folder move. The policy test keeps enforcing the crate roots.

## Risks / Not doing

- `sqlx` 0.9, `riverqueue` 0.4, `utoipa-axum` 0.3 and `axum` 0.8 are all pre-1.0. Pin exact versions in the workspace `Cargo.toml`. Do not float. Wrap River behind `crates/worker/src/queue.rs` so swapping to `apalis` 1.0 is one module.
- `utoipa-axum` 0.3 lags utoipa 6. If the route macro fights the router, drop the macro and register paths by hand in the `openapi` crate. Schema is the artifact that matters, not the macro.
- Prisma `_prisma_migrations` is not convertible. One baseline SQL file. Production cutover needs a window where that version is marked applied before Bun stops owning writes.
- Dual-running Bun and Rust against one Postgres is safe only while Rust is read-only. First write port (session login or catalog mutation) ends the dual-write story for that table. Do commerce reads first inside S8 if a table is still written by Bun.
- BullMQ at cutover: durable queues may hold pending and _delayed_ jobs (`orders-expiry` schedules days out). River does not read BullMQ. Drain the Bun worker before switching producers, or re-enqueue future expiries from the orders table. Never run both consumers against the same queue.
- River is 0.4.0 with low adoption. Do not build a queue abstraction over it beyond the one module. Do not use `apalis-pgmq` (0.1.0-rc, ~131 downloads).
- `web-push` 0.4.2 was last released in 2019. Verify it on MSRV 1.95 and with current rustls; if it fails, `ece` + `jwt` + `reqwest` is the fallback. Do not ship push on an unverified crate.
- `rmcp` 3.x validates `Host` (RUSTSEC-2026-0189 fix, loopback-only default). Behind the web rewrite the host may be loopback or the public host depending on `changeOrigin`. Configure the allowlist in S13 or every MCP call returns 403.
- MCP must not gain authority. In Rust there is no oRPC `call()`, so tools call the same domain functions as the panel handlers. A tool may never be more permissive than the dashboard call it mirrors.
- OAuth2 tokens and `McpSession` rows are keyed by digests. Keep code/token encoding and hashing byte-identical or every issued token and listed session breaks at cutover.
- argon2id parameter parity is accepted per user direction, not verified. If logins fail after S14, the cause is parameters, not session plumbing.
- RLS later: policies plus `SET LOCAL app.tenant_id` inside the S3 transaction helper. sqlx already holds the connection for the transaction, so no driver swap. Do it only after S19, in its own ADR, because a missing GUC would start failing closed and take the API down.
- Redis loses its last consumer in S17 but `infra/compose.yaml` and `REDIS_URL` stay. Removing Redis is a separate decision (cache was never built).
- Skipped: distroless images, sentry-rust, RFC 9457 errors, axum 1.0 wait, diesel, sea-orm, a new `.agents/skills` topic.
