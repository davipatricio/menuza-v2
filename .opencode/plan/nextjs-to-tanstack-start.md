## Target architecture

Hard contract. A step that violates it is a review finding, not a style preference.

```
apps/web-tanstack/
  AGENTS.md  package.json  tsconfig.json  vite.config.ts  turbo.json
  src/
    start.ts            # createStart: requestMiddleware (host allowlist, mode, tenant), CSRF
    server.ts           # only if early 404 cannot be expressed in start.ts
    router.tsx          # getRouter() factory; per-request QueryClient; routeTree
    routeTree.gen.ts    # generated, never hand-edited
    styles/globals.css  # tailwind + @theme tokens + @fontsource Inter
    routes/             # THIN ONLY
      __root.tsx
      _marketing/{route,index,about,pricing,contact}.tsx
      _storefront/{route,store,menu/index,menu/$productId}.tsx
      dashboard/…
      oauth/authorize.tsx
      $.ts              # 9 proxied mounts only; any other path returns 404
    features/
      auth/ shell/ catalog/ coupons/ customers/ orders/ settings/ integrations/ assistant/ storefront/ marketing/
        components/  hooks/  schemas/  lib/
        server/         # *.server.ts (impl) + *.functions.ts (createServerFn)
    server/             # cross-cutting server-only
      panel-client.ts  session.ts  tenant-resolve.ts  cache.ts
    components/
      ui/…              # vendored shadcn, unchanged paths
      nutrition/  assistant-ui/  # vendored, unchanged paths
      app-image.tsx     # shared cross-feature only
    lib/                # framework-agnostic
      format.ts  panel-labels.ts  utils.ts  csv-export.ts  filter-params.ts
      return-to.ts  push-subscription.ts  sw-cache-rules.ts  tools/registry.ts
    offline/            # index.ts, persister.ts, sync-queue.ts, worker-queue.ts, sw-client.ts
```

Rules:

1. `src/routes/**` contains only `validateSearch`, `loader`, `beforeLoad`, `head`, `errorComponent`, `pendingComponent`, `notFoundComponent`, `server.handlers`, and a single `<PageComponent params={…} />` line. Cap: **≤ 60 lines and no JSX beyond that one component**. No `panelClient()`, no `fetch`, no `useState`, no form logic.
2. `features/<domain>/` owns everything else. `server/` holds two kinds: `*.server.ts` (server-only implementation, may import `src/server/**`) and `*.functions.ts` (`createServerFn` wrappers — the **only** server surface a route or loader may import). `components/` and `hooks/` import neither.
3. `src/server/**` is server-only: `panel-client.ts` (cookie → oRPC client), `session.ts` (`getPanelSession`, `requireSession`), `tenant-resolve.ts` (host cache + `resolveHost`), `cache.ts` (staleTime constants + invalidation helpers). A route/loader never imports these directly: it calls a `*.functions.ts` wrapper, because route loaders are isomorphic and would drag `src/server/**` into the client bundle.
4. `src/components/ui/**` keeps upstream placement and filenames; only the `next/link`/`next/image` imports change. `src/components/*.tsx` is for genuinely cross-feature components (`app-image.tsx`); anything used by one feature lives in that feature.
5. `src/lib/**` is framework-agnostic (no React, no router, no server imports): `format.ts`, `panel-labels.ts`, `utils.ts`.
6. Import boundaries, enforced by oxlint `no-restricted-imports` per path group: client graph may not import `src/server/**`, `@menuza/orpc-server`, `@menuza/db`, `@prisma/*`; `features/*/components/**` may not import `features/*/server/**`; `src/routes/**` may import only `features/*/server/*.functions.ts` from a server folder — never `*.server.ts`, `src/server/**`, `@menuza/orpc-server` or `@menuza/db`.
7. Vendored trees (`components/ui/{reui,smoothui,magicui,motion-primitives,cult-ui,aceternity,ecomcn}`, `components/assistant-ui/**`, `hooks/*`) keep their paths in the first pass. Only their `next/*` imports change; churn beyond that is out of scope.
8. Every feature folder gets an `AGENTS.md` (Phase 9). If a file cannot be placed by these rules, the rules win — ask before adding a folder.

## Risks / Not doing

- **Bun vs Node runtime.** Next must run under Node (Turbopack hashed-external bug, vercel/next.js#86866) and Start/Vite is assumed to follow. If `vite`/`start` are launched by Bun during `bun run dev`, the SSR bundle may resolve `node:` builtins differently. Mitigation: Vite's `bin` has a Node shebang, so `vite dev`/`vite build` run under Node 24 even when spawned from a Bun script; S3 proves `vite build` under Node 24 before any product port.
- **Vite 8 plugin ecosystem.** `@tanstack/react-start@1.169.4` requires `vite >= 8`; `@vitejs/plugin-react@6` and `@tailwindcss/vite@4.3.3` declare Vite 8. Any third-party plugin added later may still peer-pin Vite 5–7. Rule: no Vite plugin beyond `@tailwindcss/vite`, `@vitejs/plugin-react`, `@tanstack/react-start`, `@serwist/vite`, `@vitejs/plugin-rsc` (spike only).
- **TS 7 + `verbatimModuleSyntax`.** The repo base sets `true` (`tsconfig.base.json:7`); Start documents that `true` leaks server bundles into the client. The new app overrides to `false` locally. `bun check` (TS 7) is the only checker; no `tsc` fallback.
- **nuqs on Start is uncovered.** The adapter is "experimental and does not yet cover TanStack Start": no `urlKeys` shorthand, trivial types only, SSR may flash defaults without `serverSearch`. Decision rule: if the products or coupons table flashes defaults on hydration, that table moves to Router `validateSearch` + `useSearch` in a follow-up — not a blocker for cutover.
- **No Next cache equivalent.** `'use cache: private'` / `cacheLife` / `cacheTag` / `revalidatePath` disappear; every removal is a deliberate read-count increase. Nothing calls `revalidateTag` today, so no correctness is lost — only the 30s/300s stale windows.
- **RSC is pre-1.0 and gated.** `@tanstack/react-start-rsc@0.1.65` + `@vitejs/plugin-rsc` may break on minor bumps. The spike is reverted wholesale on a no-go; no product code may import it.
- **Bun's TS checker vs generated tree.** `routeTree.gen.ts` must be excluded from oxlint/oxfmt, or `bun run fmt:check` will fight the generator; commit it when `typegen` cannot regenerate it standalone.
- **Two apps, one set of tests.** `apps/web/tests/**` stays untouched until S61, which moves it into the Start app and rewrites exactly 3 imports; a fourth failure means the module layout drifted and is a cutover bug, not a test bug.
- **No new dependency** beyond the Start/Vite/serwist/font/imagetools set listed in S2; `vite-imagetools` is explicitly a follow-up, not adopted here.

## Accepted limitations

1. `next/image` becomes a plain `<img>` (`app-image.tsx`). No automatic AVIF/WebP, no responsive `srcset`, no intrinsic layout reservation beyond explicit `width`/`height` + `aspect-*`. LCP on the storefront hero is the cost; adding an image-optimising Vite plugin is a later optimisation, not part of this plan.
2. `next/font/google` self-hosting switches to `@fontsource-variable/inter`; the font file ships in the bundle instead of being optimised/inlined by Next. `--font-inter` stays the token contract.
3. nuqs keeps its TanStack adapter with the documented gaps (no `urlKeys`, trivial types, possible hydration flash). The 6 parser modules and ~9 `useQueryStates` call sites are unchanged.
4. Route-level prefetching is coarser: `Link preload="intent"` replaces `HoverPrefetchLink`'s per-destination `prefetch` flip, and there is no Partial Prefetching equivalent. Navigation may fetch slightly more or later than today.
5. No `ensureStatic`/`instant` DSL: static marketing pages are static by construction (no per-request read in `beforeLoad`/`loader`), and nothing enforces it at build time.
6. Loading/error granularity is per route option, not per `loading.tsx` file; the 24 `loading.tsx` collapse into a smaller set of `pendingComponent`s.
7. The storefront and marketing ports are one step per route group, so their per-page diffs are coarser than the dashboard's.
8. Tests live on `apps/web` until S61, which moves them to the renamed app and rewrites only the 3 Next-path imports (`product-filter` ×2, `global-search-utils` ×1); `proxy.test.ts` changes its header comment only. No test is rewritten beyond that in this migration.
9. Vendored registry trees keep Next-era file paths and only get the `next/link`/`next/image` import swap; they are not reorganised into `features/`.

## Rollback

- Phases 0–9 add a second workspace and never modify `apps/web`. Rollback is `rm -rf apps/web-tanstack` plus reverting `package.json` catalog additions, `scripts/dev.ts`, `scripts/design-check.ts` and `scripts/workspace-policy.test.ts` edits, plus `.oxlintrc.json`. `bun install` restores the lockfile.
- S61 is the only destructive step. Before it: `git tag pre-tanstack-cutover` (or a branch), confirm `apps/web` is clean, and keep the Next tree recoverable via `git checkout <tag> -- apps/web`. The rename is a `git mv`, so history follows the files.
- After S61, rolling back means restoring the tag and re-running `bun install`; the Start app is additive on disk until S61, so no data, API or DB state is involved.
- S66–S68 (RSC) are reverted by dropping `@vitejs/plugin-rsc`, the `rsc` flag in `vite.config.ts`, and `src/features/catalog/rsc/**`. No other module imports them.
